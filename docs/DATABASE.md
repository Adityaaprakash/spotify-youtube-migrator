# Database Architecture & Migrations

## Overview
PostgreSQL (version 16 in production and Testcontainers) is the authoritative primary relational store for the Spotify-to-YouTube Migrator.

## Design Principles & Conventions
1. **Flyway for Migrations**: All schema modifications are versioned, linear, forward-only Flyway SQL migrations in `backend/src/main/resources/db/migration`. Existing migrations are strictly immutable.
2. **UUID Primary Keys**: Application entities use UUID primary keys generated by the application or database.
3. **Audit Tracking**: Timestamp columns (`created_at`, `updated_at`, `started_at`, `completed_at`) with microsecond/timestamptz precision.
4. **Optimistic Locking**: Critical concurrent aggregate roots (`MigrationExecution`, `ExecutionTrackRecord`) use JPA `@Version` columns (`version BIGINT NOT NULL DEFAULT 0`).
5. **Generational Fencing**: Leased operations enforce atomic generational fencing tokens (`lease_generation`) and wall-clock expiry bounds (`lease_until > clock_timestamp()`).
6. **Referential Integrity**: Hard foreign keys link users, review sessions, executions, and track records, with cascading lifecycle management where appropriate and `ON DELETE RESTRICT` for immutable audit logs.
7. **Zero Long-Running Database Transactions**: Database transactions are kept minimal and never held open across external network calls to Spotify or YouTube.

## Phase 14B Schema Enhancements (`V15`)

### 1. `migration_executions` Table Additions
```sql
ALTER TABLE migration_executions
    ADD COLUMN total_source_tracks INT NOT NULL DEFAULT 0,
    ADD COLUMN matched_tracks INT NOT NULL DEFAULT 0,
    ADD COLUMN failure_summary TEXT;

-- Backfill from total_approved_tracks for existing rows
UPDATE migration_executions
SET total_source_tracks = total_approved_tracks,
    matched_tracks = total_approved_tracks
WHERE total_source_tracks = 0 AND total_approved_tracks > 0;

-- Composite index for user migration history reverse chronological queries
CREATE INDEX idx_migrationexecutions_user_created
    ON migration_executions (user_id, created_at DESC);
```

### 2. `execution_track_records` Table Additions
```sql
ALTER TABLE execution_track_records
    ADD COLUMN destination_title VARCHAR(500),
    ADD COLUMN destination_channel VARCHAR(500),
    ADD COLUMN destination_duration_ms BIGINT,
    ADD COLUMN decision_source VARCHAR(50),
    ADD COLUMN match_score DOUBLE PRECISION,
    ADD COLUMN match_decision VARCHAR(50);
```

### 3. Guarantees & Non-Destructive Design
- **Non-Destructive**: All added columns use defaults or are nullable; existing rows are preserved without breaking changes.
- **Index Optimization**: `idx_migrationexecutions_user_created` powers high-performance paginated queries (`PageRequest.of(page, size)`) for user migration history without table scans.
- **Data Integrity**: Track counts (`total_source_tracks`, `matched_tracks`, `total_approved_tracks`) reflect accurate playlist pre-flight and review statistics.

## Phase 14D Schema Enhancements (`V16`)

### 1. `execution_audit_events` Table
```sql
CREATE TABLE IF NOT EXISTS execution_audit_events (
    id UUID PRIMARY KEY,
    execution_id UUID NOT NULL,
    event_type VARCHAR(50) NOT NULL,
    previous_state VARCHAR(50),
    new_state VARCHAR(50),
    reason VARCHAR(500),
    details TEXT,
    actor VARCHAR(100),
    correlation_id VARCHAR(100),
    rollback_record_id UUID,
    reconciliation_record_id UUID,
    created_at TIMESTAMPTZ NOT NULL,
    updated_at TIMESTAMPTZ NOT NULL,
    CONSTRAINT fk_audit_events_execution FOREIGN KEY (execution_id)
        REFERENCES migration_executions (id) ON DELETE CASCADE,
    CONSTRAINT fk_audit_events_rollback FOREIGN KEY (rollback_record_id)
        REFERENCES execution_rollback_records (id) ON DELETE SET NULL,
    CONSTRAINT fk_audit_events_reconciliation FOREIGN KEY (reconciliation_record_id)
        REFERENCES execution_reconciliation_records (id) ON DELETE SET NULL
);
```

### 2. Indexes & Performance Optimization
```sql
-- Chronological event timeline per execution
CREATE INDEX IF NOT EXISTS idx_audit_events_execution_created
    ON execution_audit_events (execution_id, created_at ASC);

-- Event type filtering
CREATE INDEX IF NOT EXISTS idx_audit_events_type
    ON execution_audit_events (event_type);

-- Status-filtered user migration history
CREATE INDEX IF NOT EXISTS idx_migrationexecutions_user_status_created
    ON migration_executions (user_id, status, created_at DESC);
```

### 3. Integrity & Retention Guarantees
- **Cascade on Parent Deletion**: If a test or administrative action purges a `migration_executions` record, audit events cascade cleanly.
- **Set Null on Compensating Action Purge**: Foreign keys to `execution_rollback_records` and `execution_reconciliation_records` use `ON DELETE SET NULL`, ensuring the audit event is never accidentally deleted if compensating records are archived.
- **Index-Only Timeline Scans**: `idx_audit_events_execution_created` covers `(execution_id, created_at ASC)` allowing fast timeline fetches without sort buffers.
- **Composite Index for Status Queries**: `idx_migrationexecutions_user_status_created` enables zero-sort queries when users filter migration history by execution status (`COMPLETED`, `FAILED`, etc.).
